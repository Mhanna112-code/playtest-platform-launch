# Excerpt proof clips (batch 35 §126 and the NDA cases)

Recorded Nov 2, 2026 on rec/excerpts (master c331ffe6) by `record.cjs` in this folder. It ran against its own dev server on port 3482 and its own database schema (`playtest_lite?schema=rec_excerpts`), with fresh throwaway accounts made through the sign-up API. Stripe was off, so Pay records "payments not set up".

How to read a clip:
- Each video shows two or three browser windows side by side, recorded at the same time: developer | tester | ….
- The coloured strip at the top of each window says whose window it is. The recorder adds it; it isn't part of the app.
- The yellow box is the recorder's wait timer. It starts at the press and counts seconds with no reload. When the change shows, the box turns green and gives the time and "same page load: yes". This is checked with a marker set when the page loaded, which a reload would clear. A red box means the change didn't show within the time allowed, and the recorder then reloads the page.
- Setup steps (posting tests, joining, sending and paying answers, and in clips 8 to 12 the developer's NDA Save) use the same APIs the pages use.

## Surprises

- **Adding or removing an NDA doesn't update profiles live (clips 8 and 11).** The excerpt does leave the profile others see, and the tester's own list does switch to "Allowed · hidden while Coral Code has an NDA" and back, but only after a reload. Neither page changed within 25 s (the red box in the video). `publicProfileV`, the profile's refresh fingerprint, includes the shown excerpt rows but not the test's NDA, and adding an NDA doesn't change those rows. Not fixed here.
- **Hover cards (clip 8):** no hover card lists excerpts. That's by design since batch 16 §23 (the test page's tester hover card has none), so there was nothing to hide there.
- **Clip 9:** the refused press redraws the page at once, so the picker leaves straight away (it doesn't wait for the 20 s check).
- **During the run (not an app result):** the local Postgres on 5499 crashed once into recovery mode, after an out-of-memory error (VirtualAlloc failed) in the 3482 dev server. It recovered by itself within about a minute, and clips 5 to 12 were then recorded again from scratch.
